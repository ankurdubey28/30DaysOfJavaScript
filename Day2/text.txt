== vs === in js

1. == performs type coercion meaning it converts type of variables being actually compared. 
   Not very strict . slower . Prone to give unexpected results.
2.  === (Strict equality) does not perform any such type coercion . strict . faster .
    Not as unpredictable as ==.
3. Object.is(val1,val2) is another equality comparator with main of comparing sameness, return 
   true if val1 and val2 have same values otherwise false. 
   Example ->  Object.is(NaN,NaN)=true and Object.is(+0,-0)=false (+0===-0 and +0==-0 are both true).

Rules for coercion/comparison
1. boolean operators converted to number (true is 1, false is 0) when being compared with non-boolean values.
2. null == undefined is true but null === undefined is false. Both these values are not equal to anything .
3. Objects (including arrays,functions) are compared using there reference not values , both for == and ===.
4. NaN is not equal to anything including itself.
5. string is converted to number when string and number are compared.
6. object is converted to primitive using toString or valueOf when object and primitive are compared.
7. null is coerced to 0 in when involved with mathematical operators
8. undefind is coerced to NaN when involved with mathematical operators
9. comparisons involving NaN and undefined are always false.

Falsy Values
These are values that are considered false when evaluated in a boolean context:

false
0 (zero)
-0 (negative zero)
0n (BigInt zero)
"" (empty string)
null
undefined
NaN


Truthy Values
All values that are not falsy are considered truthy. This includes:

true
Any non-zero number (e.g., 42, -42, 3.14)
Any non-empty string (e.g., "0", "false")
Arrays (e.g., [])
Objects (e.g., {})
Functions
Dates (e.g., new Date())
Any BigInt value other than 0n

A. Optional Chaining Operator: (?.)
The optional chaining (?.) operator accesses an object's property or calls a function. 
If the object accessed or function called using this operator is undefined or null, the 
expression short circuits and evaluates to undefined instead of throwing an error.

B. Nullish coalescing operator:(??)
The nullish coalescing (??) operator is a logical operator that returns its right-hand side operand when its left-hand side operand is null or undefined, and otherwise returns its left-hand side operand.
Its main job can be understood as giving fallback value to the variable in case main value is
null or undefined only.

Q. How is || operator different from ??.
A. ?? is a special case of || operator in sense that both give fallback value , but || does this for falsy values on left hand side while ?? does this for only null and undefined on left hand side.

C. Spread  operator:
1. spread only works with iterable values like array and string.
2. spreading an object , js copies only own enumerable properties (Properties that are directly on the object and not hidden from loops).
 eg-:    const array = [1, 2, 3];
         const obj = { ...array }; // { 0: 1, 1: 2, 2: 3 }

         const obj = { ...true, ..."test", ...10 };
         console.log(obj); // { '0': 't', '1': 'e', '2': 's', '3': 't' }
4. When it comes to copying things with spread operator, it goes only one level deep which means
   only shallow copy is made.
5. Property overriding - when multiple properties with same key are found while spreading, the 
   latest value is assigned.
6. spread operator is used to conditionally add properties specially in ReactJS.

D. Rest operator:
1. rest operater creates a an entire newly allocated array of condensed values.
2. since rest operator creates a new array only , all array methoda are applicable here
   which is not he case with arguments which is an object type with limited methods with it.
